# 築本模板工程計算　驗收標準

本文件是軟體「算得對」的定義。每一條都有編號，對應 `tests/` 裡同編號的自動化測試。
**自動化測試全部通過，程式才算驗收合格，才能合併上線。**

- 執行測試：`npm test`（第一次先 `npm ci` 與 `npx playwright install chromium`）
- 狀態說明：✅ 已有測試且通過　⏳ 已寫測試、程式待實作（測試標為 TODO，不擋合併，但要列入下一步）　❓ 待使用者決定，先不寫測試

## 一、計算規則（`tests/rules.test.js`）

期望值是依規則手算，不是從程式抄來的。

### 柱

| 編號 | 驗收標準 | 狀態 |
|---|---|---|
| AC-C01 | 柱模板 = 2(b+h)×(H−版厚)×支數；混凝土 = b×h×(H−版厚)×支數 | ✅ |
| AC-C02 | 柱模板扣除樑柱接頭面積 | ✅ |
| AC-C03 | 圓柱模板 = π×D×(H−版厚)；混凝土 = π×D²/4×(H−版厚) | ✅ |
| AC-C04 | 柱高未個別指定時用該層層高，版厚用專案版厚 | ✅ |

### 樑

| 編號 | 驗收標準 | 狀態 |
|---|---|---|
| AC-B01 | 樑模板 = (b + 2(h−版厚))×淨跨；混凝土 = b×h×淨跨 | ✅ |
| AC-B02 | 中間樑**不**補「版厚×無版長度」（使用者規則 2026-10-27） | ✅ |
| AC-B03 | 只有邊樑補「版厚×無版長度」 | ✅ |
| AC-B04 | 樑底下有牆的長度，扣 牆厚×長度 | ✅ |
| AC-B05 | 樑混凝土含轉角塊長度 | ✅ |

### 基礎

| 編號 | 驗收標準 | 狀態 |
|---|---|---|
| AC-G01 | 中間地樑雙面模，模板高 = 樑深 − 基礎版厚 − 1 樓版厚，不組底模；混凝土 = 寬×該高度×長 | ✅ |
| AC-G02 | 周邊地樑只組內側單面模 | ✅ |
| AC-G03 | 基礎版厚專案設定沒填時，取圖面（尺寸表）讀到的厚度 | ✅ |
| AC-G04 | 基礎版混凝土 = 面積×基礎版厚，不組模 | ✅ |
| AC-G05 | 1 樓地板混凝土 = (面積 − 電梯坑開口)×版厚，不組模 | ✅ |

### 牆

| 編號 | 驗收標準 | 狀態 |
|---|---|---|
| AC-W01 | 牆模板 = 2×長×(層高 − 上方樑深)；混凝土 = 長×高×厚 | ✅ |
| AC-W02 | 牆上方沒有樑時，高度算到樓版底（層高 − 版厚） | ✅ |
| AC-W03 | 門窗開口（依門窗表）兩面都扣，混凝土扣開口體積 | ✅ |
| AC-W04 | 女兒牆用女兒牆高度計算 | ✅ |

### 版

| 編號 | 驗收標準 | 狀態 |
|---|---|---|
| AC-S01 | 真實模板 = 原始模板 + 封模 − 扣版牆接頭 − 扣柱頭；混凝土 = 原始模板×版厚 | ✅ |
| AC-S02 | 版的欄位可輸入算式 | ✅ |
| AC-S03 | 不組模的版（如 FCS 落地版）只算混凝土 | ✅ |

### 其他

| 編號 | 驗收標準 | 狀態 |
|---|---|---|
| AC-O01 | 樓梯 = (斜版長×梯寬 + 級高×梯寬×階數)×座數，歸「其他」 | ✅ |
| AC-O02 | 樓梯平台底模 = 寬×深×處數×座數，歸「版」 | ✅ |
| AC-O03 | 陽台垂牆 = (版厚 + 2×垂深 + 牆厚)×長；混凝土 = 厚×垂深×長 | ✅ |

### 樓層歸屬與總表

| 編號 | 驗收標準 | 狀態 |
|---|---|---|
| AC-F01 | 第 N 層 = 本層柱、牆 + 上一層結構平面的樑、版（二層結構平面 → 1 樓） | ✅ |
| AC-F02 | 屋突一層結構平面 → 最上層；屋突二層 → R1 | ✅ |
| AC-F03 | 每層範圍 = 本層樓板面到上一層樓板面（基礎～1FL、1FL～2FL…） | ✅ |
| AC-F04 | 分層總表依樓層、類別加總（樓梯 → 其他、平台 → 版） | ✅ |

### 圖面缺值

| 編號 | 驗收標準 | 狀態 |
|---|---|---|
| AC-M01 | 結構圖上沒有編號的柱，照常計算，但列入辨識檢查提醒 | ✅ |
| AC-M02 | 基礎版厚圖面沒標、專案也沒填時，仍要計算，但要**標紅**提醒（不可默默用預設值） | ⏳ 目前用預設 0.4 m 且沒有標示 |

## 五、基準怎麼改

1. 只有使用者明確確認新規則或新數字後，才能改 `tests/expected/`。
2. 先改測試（或新增驗收標準），確認測試失敗，再改程式讓它通過。
3. 執行 `npm run test:update` 更新基準，PR 說明要列出哪些樓層、哪些數字從多少變成多少，以及使用者哪一句話確認的。
4. 新的測試案（使用者提供的新案子）：圖檔放到專案共用資料夾 `zhuben/tests/drawings/`，在 `tests/projects.test.js` 的 `SETS` 加一筆，更新基準。
